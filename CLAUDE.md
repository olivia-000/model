## Architecture

MVC PyQt5 application for 5-channel bridge structure + AC road damage detection, mounted on a firetruck. **Not** vehicle detection — the truck is the inspection platform.

### MVC Structure (`firetruck_detection/`)

- **`main.py`** — Entry point. Wires `Detection` (Model) → `DetectionGUI` (View) → `DetectionController`, starts Qt event loop.
- **`model/detection.py`** (`Detection`) — Top-level model. Manages 5 `Detector` workers and runs the shared batch inference thread (`MULTI_MODEL=False`). Exposes get/set methods for all GUI-controlled parameters; persists changes to `my_last_settings.yaml`.
- **`model/detector.py`** (`Detector`) — Per-channel worker. Owns a `VideoStream`, `PostProcessingWorker`, fetch thread, and result thread. Receives `(bridge_result, road_result, frame, timestamp)` tuples from the shared inference thread via `result_queue`.
- **`model/post_processing.py`** (`PostProcessingWorker`) — Stage 2 YOLO-CLS for expansion joint classification (height diff on ch1/ch3, blockage on ch4).
- **`model/vlm_worker.py`** (`VLMWorker`) — Async LLM Stage 2 alternative. One shared instance; per-channel queues + cooldown. Supports Gemini, Claude (anthropic SDK), and Qwen-local (vLLM via OpenAI-compatible API).
- **`utils/__init__.py`** — All system-level constants: `NUM_VIDEO_STREAMS`, `MULTI_MODEL`, `SPEED`, `VIEW_DOWNSCALE_RATIO`, `CROPPING_THRESHOLD`.
- **`ultralytics/`** — Vendored Ultralytics. Use this, not the system-installed package.

### Threading Model (`MULTI_MODEL=False`, default)

```
Detection._inference_worker (1 thread)
  ├── bridge_model([5 frames], batch)   → main_results[0..4]
  ├── road_model([ch2, ch5], per-ch)    → road_results[2, 4]
  └── workers[i].result_queue.put(...)

Per Detector (5 workers, each):
  ├── fetch_thread    — reads frames from VideoStream into last_frame
  └── result_thread   — drains result_queue, draws bboxes, triggers Stage2/VLM
```

### Camera Layout

| Channel | Position | Purpose |
|---------|----------|---------|
| ch1 | Right | Bridge right side, expansion joint height diff |
| ch2 | Front | AC road damage detection |
| ch3 | Left | Bridge left side, expansion joint height diff |
| ch4 | Back-Down | Expansion joint blockage |
| ch5 | Back | AC road damage detection |

### Detection Logic

**Stage 1 — Bridge (10 cls, all 5 channels)**:
```
0=spalled concrete, 1=corroded bolt, 2=expansion joint, 3=normal drainage hole,
4=abnormal drainage hole, 5=normal bolt, 6=block expansion joint,
7=rust steel pipe, 8=barrier damage, 9=blocked drainage hole
```
Abnormal classes (red): `[0,1,4,6,7,8,9]`. Normal (green): `[2,3,5]`.

**Stage 1 — Road Damage (4 cls, ch2/ch5 only)**: crack/pothole types.

**Stage 2 — YOLO-CLS** (triggered when Stage1 detects cls 2 or 6):
- ch1, ch3: height difference model — crop bbox, classify
- ch4: blockage model — uses **whole frame** (not crop)

**Per-channel rules** (from `channel_rules` in config):
- ch4: only show cls 6 from bridge model (`bridge_allowed_class_ids: [6]`)
- ch2, ch5: ignore road damage bboxes with center-y < 0.5×H (`road_filter_bbox_y_ratio: 0.5`)

### VLM Integration

`VLMWorker` is an alternative Stage 2 (method: `vlm` vs `yolo_cls`). Triggered on same cls 2/6 detections. Results are **async** — they never appear on live video; only in GUI log and saved annotated images. Switch provider/model at runtime via GUI without restart.

## Configuration

**Primary**: `firetruck_detection/cfg/default_settings.yaml`
**Runtime overrides**: `firetruck_detection/cfg/my_last_settings.yaml` (auto-generated by GUI)

Key config structure:
```yaml
detection_modules:
  bridge:
    enable: true
    channels: [ch1, ch2, ch3, ch4, ch5]
    weight: '<filename without .pt>'   # from weights/
    conf: 0.3
    stage2:
      enable: true
      method: 'yolo_cls'               # or 'vlm'
      trigger_class_ids: [2, 6]
      per_channel:
        ch1: { weight: '...', task: height }
        ch3: { weight: '...', task: height }
        ch4: { weight: '...', task: gap }
  road_damage:
    enable: true
    channels: [ch2, ch5]
    weight: '<filename without .pt>'
    conf: 0.3
channel_rules:
  ch4: { bridge_allowed_class_ids: [6] }
  ch2: { road_filter_bbox_y_ratio: 0.5 }
  ch5: { road_filter_bbox_y_ratio: 0.5 }
source: 0                              # 0=video files, 1=RTSP
test_video_dir: /path/to/dir          # must contain ch1/ .. ch5/ subdirs
```

All weights must be in `firetruck_detection/weights/<name>.pt`.

## ROS Version (`bridge_check_ROS/`)

`bridge_check_ROS/src/Yolov8_ros/` is the catkin source that gets copied into the Docker workspace at `/catkin_bridge_ws/src/Yolov8_ros/` and built there. Key packages:

| Package | Role |
|---------|------|
| `yolov8_ros` | Main node (`multi_camera_detection_node.py`) + launch files |
| `yolov8_ros_msgs` | `BoundingBox.msg`, `BoundingBoxes.msg` |
| `yolov8_ros_box_image_msgs` | `BoundingBoxesWithImage.msg` |

Build & run (inside Docker container `ros_yolo_bridge`):
```bash
cd /catkin_bridge_ws && catkin_make -DPYTHON_EXECUTABLE=/usr/bin/python3.8
source /catkin_bridge_ws/devel/setup.bash
LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libffi.so.7 \
  roslaunch yolov8_ros yolo_v8_multi_camera_unified.launch device:=cuda
```

Node shebang must be `#!/opt/conda/envs/yolov8_rtx5090/bin/python3.10` (RTX 5090 / sm_120 requires PyTorch 2.7+ via conda Python 3.10; Python 3.8's max is PyTorch 2.3.x which doesn't support sm_120).

`LD_PRELOAD` is required to fix `libp11-kit` libffi symbol conflict between conda and system libraries. `source` must come before roslaunch in every new terminal.

Rosbag playback:
```bash
rosbag play -l -r 0.5 /workspace/your_recording.bag
```

`smaple/MIGRATION_GUIDE.md` documents the full porting guide. Key constraints:
- Downstream GPS node subscribes to `BoundingBoxes` / `BoundingBoxesWithImage` — topic names and msg fields are frozen.
- No GUI, no LLM, no email/web-api in the ROS version.
- Single integrated node, not per-channel nodes.
- `smaple/Yolov8_ros/` contains older reference scripts (pre-unified node).
